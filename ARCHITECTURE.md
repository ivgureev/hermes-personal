# Архитектура MVP

## Контур запроса

1. Пользователь вводит запрос в чате.
2. Детерминированный классификатор определяет уровень риска.
3. Запрещённый запрос блокируется.
4. Средний или высокий риск создаёт неизменяемую карточку параметров подтверждения.
5. Низкий риск передаётся модели вместе с системным промтом и историей текущей сессии.
6. Ответ и фактический статус записываются в SQLite.

## Компоненты

| Компонент | Ответственность |
|---|---|
| Streamlit UI | Чат, задачи, файлы, подтверждения, журнал, настройки |
| Risk Gate | Блокирование и запрос подтверждения до исполнения |
| LLM Adapter | OpenAI-compatible API, таймаут, обработка ошибок |
| SQLite | Сообщения, задачи, файлы, решения, аудит |
| Local File Store | Файлы под случайными именами, SHA-256 |
| System Prompt | Роль, режимы, правила качества и безопасности |

## Развитие

Следующая версия может заменить прямой LLM-вызов на совместимый Hermes Agent backend. UI при этом остаётся контрольной оболочкой: запросы идут в агентный цикл, вызовы инструментов отображаются в журнале, а привилегированные операции блокируются серверным approval gate. Подтверждение нельзя реализовывать только инструкцией в промте: оно должно проверяться на уровне диспетчера инструментов.
